## 1. 项目定位

- **性质**：校内/院级比赛或课程结题，答辩导向。
- **窗口**：两周，软 deadline；人力 3 人 × 每周 15 小时 ≈ 90 人时。若确认硬截止日，立即重排。
- **开发模式**：AI Agent 编码 + 人类下指令/审查/调试；spec 文档是唯一事实源，改码先改 spec。
- **成功标准**：现场端到端演示（Claude Code 状态上屏 + 实体 Yes 键授权 permission）+ 可讲述的创新叙事 + 可复现的仓库。

## 2. 创新叙事（答辩主线）

1. **主线①「真开源补完」**：参考项目硬件开源、软件闭源、协议无文档；本项目交付全栈开源（固件 + daemon + 协议规范），把"看得见摸不着"变成"任何人可接入"。零额外成本——代码本来就要写，故事来自姿态。
2. **副线②「一实一虚」**：浏览器虚拟设备与实体设备说同一套协议（传输层抽象 USB CDC/TCP），现场演示协议开放性。约 10 人时，可砍。
3. **话术③全离线**：ASR 等外部服务接口可插拔本地实现（如 Whisper），仅作答辩承诺，本期不实现。

## 3. 与参考项目的关系（合规边界）

- HachimoDock 软件实际为私有二进制许可（release 附 Binary Distribution License，禁止逆向；其公开页面的 GPL-3.0 声明与事实不符）。
- 本项目策略：**纯干净室**——不接触作者；不使用解包所得的协议命名、字段、代码；仅采纳业界通用常识（hooks 机制、`claude -p --resume` 会话注入、NDJSON 线协议均为公开通行做法）。
- 解包产物封存于项目外目录，禁止进入本仓库与任何编码 Agent 的上下文。
- 官方固件的剩余价值：硬件链路已验证的证明、演示保险（可随时刷回）、UX 行为参考。
- 工作量锚点：官方 bridge JS 实测 13,238 行/42 文件，全功能版估算 4-6 万行。**本项目不以功能对齐为目标。**

### 4.4 v3.1 增补：语音与统计包（2026-09-07 grill 定稿）

MVP 四项 2026-09-06 真机全通过，窗口余量下经多轮技术路线拷问增补三项：

| 编号 | 功能 | 路线（grill 定稿） |
|---|---|---|
| F12 | 语音输出（TTS 播报） | daemon 侧：macOS `say` / Windows PowerShell SAPI / Linux espeak-ng；念 waiting_confirm/done/error 与 permission 结果；`PETLINK_VOICE=1` 开关（默认关，含 3s 冷却防刷） |
| F13 | 会话统计 | daemon 侧 `GET /stats`：hook 事件计数、五态分布与停留时长、permission allow/deny/none、按键计数、语音转写打点——结题报告的数字来源 |
| F14 | 语音输入（PTT） | 板载模拟麦经 ES8311 codec（I2S STD RX，16kHz/16bit/mono）→ 协议 v1.2 `audio` 帧分块上行（UART 115200→921600）→ daemon 重组 → 本地 whisper.cpp small（466MB，不入仓库）转写 → tmux send-keys 注入。触发=v0.8 起为专用 VOICE 键按住说话（按下录音、松手上传，上限 30s 自动截断，<500ms 误触丢弃；≤v0.7 为空闲态长按 YES 录 6s 定长）。`waiting_confirm` 期间语音让位按键裁决。不做语音权限（permission 语音裁决）——注入通道统一为自由文本 |

边界约束（沿用宪法）：模型与二进制不入仓库（.gitignore 排除）；ASR 全本地（兑现主线③"全离线"）；语音输入是尽力而为通道（分块不重传，丢段即弃，绝不能拖垮按键授权主链路）。

### 4.5 v3.2 增补：token 消耗显示（2026-09-09 grill 定稿）

| 编号 | 功能 | 路线（grill 定稿） |
|---|---|---|
| F15 | token 消耗显示 | **数据源**：hook 载荷自带的 `transcript_path`（会话流水 JSONL）——daemon 增量 tail（记 offset 只读新行），取 assistant 消息的 usage 四项（input/output/cache_creation/cache_read）。不依赖 hook 载荷带 usage（常规事件不带，Stop 只有金额汇总）。**双口径**：`ctx` = 最新一条 usage 四项之和（此刻上下文占多大，compact 后自然回落）；`tot` = 历次累加（本会话共烧多少，单调递增）。主线程口径（Task 子代理的独立 transcript 不计入）。**下发**：state 帧可选 `tokens` 字段（协议 §3.4，旧设备忽略）；多会话时为焦点会话的口径。**UI**：实体板/虚拟设备顶栏标题下方常驻小字（ASCII 缩写，如 `ctx 45k / tot 1.2M`；初稿定在底部，真机发现与状态胶囊/text 短标签重叠，同日上移）；语音播报不念。**刷新**：hook 事件即刷 + 焦点会话 5s 轮询兜底（长回合无事件时也能动） |

边界：transcript 只读不写（旁路观察，零侵入 Claude Code）；文件换路径/变短（compact、rewind）则整重扫该文件；解析失败静默降级为不显示，绝不影响状态主链路。

### 4.6 v3.3 增补：状态提示音（2026-09-09 grill 定稿）

| 编号 | 功能 | 路线（grill 定稿） |
|---|---|---|
| F16 | 状态提示音 | **触发**：状态转移进入 waiting_confirm / done / error 三态（与 F12 播报集一致）；同状态重复帧不响（重连重放、周期刷新不吵）。**硬件**：板载 ES8311 DAC → NS4150 功放（PA_Ctrl=GPIO53 高使能）→ 板载喇叭接口外接 8Ω 无源小喇叭；I2S DSDIN=GPIO9。**实现**：固件内正弦合成 16k/16bit/mono 提示音（无素材文件、无新增资产分区），每段加 5ms 线性包络防爆音。音色：waiting_confirm=双高音（急）、done=低→高上扬（悦）、error=单低音（沉）。**并发**：与语音输入共用 duplex I2S 通道 + 单 codec（ADC|DAC），录音优先——mic 忙时提示音直接丢弃不排队。**配置**：Kconfig 开关 + 音量（默认约 70）。**降级**：I2C 探不到 ES8311 / 播放失败只记日志，绝不拖垮状态主链路（同 F14 语音输入的兜底哲学） |

边界：B 档（daemon TTS 音频流下发、板子念整句）明确不做——09-19 结题窗口下防蔓延，且 F12 已覆盖"念内容"场景；外接喇叭规格 4~8Ω 无源（NS4150 3W D 类对口），板子不自带喇叭属硬件事实。

### 4.7 v3.4 增补：三键改版——废除长按拒绝，语音改专用键按住说话（2026-09-12 grill 定稿）

动机：①"长按 YES=拒绝"要求演示现场按准 600ms，手感风险高（NO 独立键早已因此增补）；②原版哈基米机的交互本就是"长按唤醒语音"（PTT），用户习惯应对齐；③复刻底板（原作开源硬件方案三：微雪 ESP32-P4 核心板 + 三机械轴底板）已打板，物理上就是三键。

| 项 | 旧（≤v0.7.1） | 新（v0.8） |
|---|---|---|
| YES 键 | 短按 <600ms=放行，长按 ≥600ms=拒绝 | **任意按下松开=放行**（无时长判档） |
| NO 键 | 按下即拒 | 不变 |
| 语音触发 | 空闲态长按 YES，松手后录 6s 定长 | **专用 VOICE 键按住录音、松手上传**（PTT），上限 30s 自动截断并照常上传，<500ms 误触本地丢弃 |
| 引脚 | YES=GPIO21、NO=GPIO22（杜邦线临时接线） | YES=GPIO50(SW1)、NO=GPIO49(SW2)、VOICE=GPIO5(SW3)，全部 Kconfig 可改（VOICE=-1 可退回双键布局） |

兼容与边界：daemon 对旧固件遗留的 `yes+long` 帧按放行处理（长按拒绝语义废除，不再按时长定档）；VOICE 键不上行 `button` 帧（PTT 在固件本地消化，不占协议仲裁通道）；授权等待期语音让位按键裁决（`voice_armed` 门控不变）。

### 4.8 v3.5 增补：摇杆导航——切焦点、切 Mac 视图、注入跟随（2026-09-14 grill 定稿）

动机：复刻底板自带 5kΩ 自回中模拟摇杆且已焊接（v3.4 划在范围外时它还没焊）；NO 键单键循环只能顺序单向翻，方向输入是交互升级；语音注入目标锁死 `PETLINK_INJECT_PANE` 环境变量是已知临时补丁（多 pane 时放弃注入的坑踩过），摇杆给了翻案的时机。

| 编号 | 功能 | 路线（grill 定稿） |
|---|---|---|
| F17 | 摇杆导航 | **固件**：摇杆 X 轴占一个 ADC 脚（Kconfig `PETLINK_GPIO_JOY_X`，默认 21；实板原理图读数 X=GPIO21 / Y=GPIO20，均 ADC1 空闲脚，Y 本期不接仅记档）。ADC oneshot 12bit + curve fitting 校准，上电采 32 次取均值做中心校准（自回中电位器有漂移）；死区 + 迟滞（进入 30% 出来 18%，防临界抖动）；越过死区沿触发一次，持续按住每 400ms 自动重复。**左右推动 → `button` 帧 `prev`/`next` 键值**（协议 §3.5 复用，新增 key 词表，旧 daemon 忽略未知 key——前向兼容不升版）。**触发门控**：已握手且无 permission 挂起（`waiting_confirm` 时摇杆让位，与语音同门控哲学）。**daemon**：`prev`/`next` → 焦点会话双向切换（`focus.cycle(-1/+1)`，NO 键循环变为其 +1 特例）；焦点会话记录其 tmux pane（petlink-hook 转发器上报 `$TMUX_PANE`），切换时 `tmux select-window` + `select-pane` 把 Mac 终端视图同步切过去；语音注入目标改为焦点会话的 pane（`PETLINK_INJECT_PANE` 环境变量保留为强制覆盖） |

明确边界：上下轴与斜向本期不用（预留——Kconfig 只设 X 轴一项，Y=GPIO20 读数记档不接；将来要用再补 Kconfig + 接线，UI 无需改）；摇杆按下轴（SW）不接（按键三键已够，避免与 VOICE PTT 语义冲突）；不驱动 macOS 系统级窗口（Accessibility/AppleScript 特权 API 明确不碰——"切窗口"由 tmux select-window/select-pane 在终端层面兑现，干净且零授权）。

兼容与迁移：旧固件无摇杆帧、旧 daemon 收到 `prev`/`next` 走 unknown key 忽略路径，互不伤害；`npm run demo` 的 `PETLINK_INJECT_PANE=pet:0.0` 语义从"唯一指定"降级为"强制覆盖"，无多 pane 场景行为不变。

## 6. 通信协议 v1（自研）

- **线格式**：NDJSON（一行一条 JSON，UTF-8）
- **传输层抽象**：USB CDC（实体设备）/ TCP（虚拟设备与调试回环），帧层接口统一
- **消息集 v1**：`hello` / `hello_ok`（含协议版本与设备信息）、`heartbeat`、`state`、`button`、`error`；v3.1 增补 `audio`（语音分块上行，§3.7——应用层分块，不属帧层资源传输机制）；其余资源分块传输仅预留命名空间，本期不实现
- **版本协商**：hello 携带 `ver`；不匹配则回 error 并拒绝或降级
- **命名规范**：本项目自定（snake_case），与任何第三方实现无重合义务
- **交付物**：`docs/protocol.md`——固件、daemon、虚拟设备三方共同的实现依据

## 7. 软件架构

```text
Claude Code
 ├─ hooks：SessionStart / UserPromptSubmit / PreToolUse / PostToolUse / Stop / Notification …
 └─ PermissionRequest HTTP hook（阻塞式）────────┐
                                                 ▼
                                   Node daemon（桥）
                        ├─ hooks HTTP 服务（状态 + 许可决策）
                        ├─ 状态归一化（→ F01 五状态）
                        ├─ 串口 / TCP 客户端（协议 v1）
                        ├─ 注入 adapter：permission 决策 ／ tmux send-keys 文本注入
                        └─ localhost 状态页
                                                 │  USB CDC ／ TCP
                                                 ▼
                                   ESP32-P4 固件（ESP-IDF + LVGL）
                        ├─ USB CDC 协议解析与分发
                        ├─ 状态机 → LVGL 宠物 UI（5 状态）
                        ├─ GPIO 按键（消抖，按下/松开沿）→ button 上报（VOICE 键 PTT 固件本地消化，不上行）
                        └─ 屏幕点亮（esp_lcd MIPI-DSI）
```

- **桌面端**：Node.js daemon（非 Tauri）；localhost 页面只做连接/版本/测试
- **固件**：ESP-IDF 5.x + LVGL；底座采用 Espressif 官方示例（Apache-2.0），不使用微雪 demo 代码（许可不明）
- **注入双路径**（permission 决策 / tmux 文本注入）收敛于同一 adapter 接口——架构得分点

## 8. 开发模式与分工

- **Day-1 Agent 实验**：纯 Agent 开发一天出可跑结果——协议 spec 草案 + daemon 骨架（假状态流）+ LVGL 模拟器 UI，全部无需硬件；验收 = 模拟器宠物随假状态流变脸。记录速度与人审成本，据此确定正式分工。
- **正式分工**（实验后确认）：固件+硬件 bring-up ／ 桥接+hooks+注入 ／ 产品+答辩，三域各一人。
- **仲裁**：协议、状态语义、模块边界由单一仲裁者终裁。
- **仓库规范**：每个域一份 spec 文档，作为 AI Agent 的唯一事实源。
