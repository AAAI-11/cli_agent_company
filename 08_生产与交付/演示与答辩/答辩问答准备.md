# 答辩问答准备(现场询问环节)

> 定位:演示脚本是"讲什么",本文是"被问怎么答"。
> 核心事实:本项目采用 **AI Agent 编码 + 人工审查/决策** 的开发模式——这是
> 需求文档 Day-1 定下的实验性流程,不是事后借口。答辩时**主动讲清这个模式**,
> 比被问到再承认,姿态完全不同。
> 用法:每题先自己作答(写在纸上或口头),再对照参考答案查漏。**不要背**——
> 评委要的是你懂,不是复读。

## 一、先想清楚:你能答什么、怎么分工

答辩前和队友对一次分工口径:

- **你(主要负责人)**:系统架构、协议设计、每个 bug 的根因与修法、技术取舍。
  这份文档覆盖的内容。
- **队友**:各自实际参与的模块(硬件接线/测试执行/文档/演示操作),答自己做过的事。
- **红线**:队友答不上你负责的部分很正常,反之你答不上队友做的具体接线也是
  正常——**不要抢答不熟的领域,说"这部分是 XX 负责的,我补充整体架构"比硬编强**。

**最重要的一条**:评委问"这代码都是你写的?"——标准答案是:
> "开发模式是 AI Agent 编码、我做架构决策和逐行审查,需求文档(宪法)和每次
> 需求变更的 grill 记录都在仓库里,git 历史可查。AI 写代码,但**每个真机 bug
> 都是我们自己定位、自己修的**——比如提示音无声那次,寄存器全对但喇叭不响,
> 最后靠电平探针发现是 DMA 时序问题。"

这个答案的杀伤力在于:它把"AI 写的"转化成"**我具备审查 AI 代码和独立排障的
能力**"——后者才是老师想验证的。

## 二、必考题(几乎一定会问)

### Q1 为什么不用现成的方案(MQTT/HTTP/现成伴侣硬件)?

参考:三层理由。① 比赛性质:干净室自研是题目要求(补完生态的叙事),协议是
核心交付物之一;② 技术判断:伴侣设备链路是**单向短报文 + 弱网容忍**,MQTT
的 broker 模式反而引入中间件依赖,NDJSON over 串口/TCP/WS 三链路同语义、
零依赖;③ 我们要的不只是"能用":hooks 状态归一化、授权仲裁这些逻辑粘在
现成协议上反而别扭。**诚实补丁**:MQTT 裁剪记录在需求文档口径段,不是没
考虑,是权衡后砍的。

### Q2 协议怎么设计的?为什么 NDJSON?

参考:NDJSON = 每行一个 JSON 对象。选它的理由:① 串口天然按行分帧,
`LineFramer` 不用处理二进制转义;② 人可读——排障时 `nc localhost 7333`
手打协议就能调试,演示也能给学生看;③ 前向兼容靠"未知字段静默忽略",
v0.5 的 bubbles 字段就是活例子——旧固件收到新帧行为不变。代价是体积比
二进制大,但我们的帧都是 4KB 内短帧,语音走 base64 分块,带宽实测够用。

### Q3 实时性怎么保证?(老师喜欢问性能)

参考:有数字。状态切换到上屏 **max 75ms(预算 500ms)**;为达到它做过一次
真优化——PNG 素材最初解码发生在渲染期,~500ms/张卡满预算,改成开机预解码
入缓存后 max 75ms。这个优化故事可以展开:发现问题靠的是固件日志的
`applied=Nms` 度量打点,**先度量再优化**,不是拍脑袋。

### Q4 授权仲裁怎么保证安全?(功能安全)

参考:三段式。① 权限请求经 `POST /permission` 挂到 daemon,35 秒超时;
② 板上按键裁决:YES 放行/NO 拒绝(v0.8 三键改版:废除长按拒绝的 600ms 时长
判档,任意按 YES 即放行——演示现场不用掐时长)——**超时不按回落 Claude Code
原生终端弹窗**,安全语义永不降级(板子死了也不断链);③ hook 只返回
allow/deny 决策,**不碰命令内容**,命令执行仍在 Claude Code 沙箱里。

### Q5 演示挂了怎么办?(压力测试)

参考:架构卖点之一就是"增强通道尽力而为,主链路绝对可靠"。板子挂了→虚拟
设备同协议顶上(一实一虚同源);语音挂了→打字;授权挂了→超时回落终端弹窗。
**演示脚本第三节就是兜底预案表**——照着答,顺便把"这本身是设计"讲出来。

## 三、高频追问(技术深度,准备好展开讲)

### Q6 麦克风那个 bug 具体怎么定位的?(排障方法论,最能证明能力)

这是你最强的素材,三段式讲:

1. **现象**:v0.4.0 按网上资料把板载麦当 PDM 直连,录出来 6 秒里 5.6 秒是
   **精确零**,whisper 转写出"字幕组署名"幻觉(近静音输入的典型症状)
2. **差分定案**:加增益旋钮→瞬态幅度变了(数字路径活着);加槽位翻槽→波形
   **一模一样**(数据线根本没动)→ 结论:DIN 恒定电平,**麦克风根本没在驱动
   这根线,引脚就是错的**
3. **正名**:查微雪官方 wiki(只查硬件数值不查代码,干净室合规)——板上
   根本没有 PDM 麦,是模拟麦→ES8311 codec→I2S。三天,PDM 悬案终结

升华一句:"错误的前提不会因为调试努力而变对——差分证据比日志更诚实。"

### Q7 提示音无声那个 bug 呢?(最近的,细节最熟)

同样是好故事:日志全绿(寄存器对、write 成功)但喇叭不响。两层真凶:
① 合成缓冲按 mono 算容量,stereo 交错后截半——DONE 提示音 270ms 只播了
90ms;② `write()` 返回不等于播完——数据还在 DMA 环里,而 `i2s_channel_disable`
是立即停振不排空,提前 close 等于掐音。教训:"**全绿日志不等于信号在跳**,
终审判据只能是耳朵或电平探针这类物理证据。"这两个 bug 的完整破案记录在
《功能与排障手册.md》§3.3。

### Q8 AI 写的代码,你怎么保证质量?(直球质疑)

参考:四道关卡。① **测试**:固件宿主单测 82 项 + daemon 冒烟 39 项,每次
提交前跑;历轮实操测试暴露的真 bug(idle 卡屏/气泡赖屏/error 无声等),
**每个都当场补了回归测试**;② **真机验收**:
功能清单里每项都有"✅ 真机+日期",没有"应该能跑";③ **宪法流程**:新增功能
先过 grill(需求拷问)写入需求文档再动手,需求变更可追溯;④ **人工审查**:
每行代码我都读过,关键路径(协议分帧/权限仲裁/音频时序)是逐行抠的。

### Q9 多会话怎么管理的?(F02R 架构题)

参考:焦点制。单屏一次只演一个会话(焦点),其余以顶栏气泡显示状态色;
焦点规则按优先级:**waiting_confirm 无条件抢占**(不错过任何授权)>焦点
超时淘汰>空闲态 NO 键循环切换。协议层 bubbles 是可选字段,旧设备忽略
即退化单会话——前向兼容的第二个活例子。

### Q10 会话统计/token 显示的数据从哪来?

参考:token 是**旁路只读**解析 Claude Code 的 transcript 文件(hook 载荷
自带路径),不侵入 Agent 本身;增量解析,双口径(ctx=最新一次上下文占用,
tot=累计消耗),5 秒轮询兜底长回合。统计(/stats)是 hook 事件全量打点,
结题报告的数字就来自这里。

### Q11 摇杆导航怎么做的?为什么要做?(F17 架构题)

参考:固件侧是**纯逻辑状态机 + 硬件读数分离**——自回中电位器有漂移,不信
理论中点,上电 32 次均值做中心校准;死区/迟滞(进入 30% 触发、退回 18% 复位)
防临界抖动;沿触发 + 按住 400ms 自动重复。状态机零硬件依赖,宿主机 24 项
单测。daemon 侧 prev/next 双向切焦点,**会话↔tmux pane 映射**靠 hook 转发
$TMUX_PANE(在 Claude Code 的 pane 里拉起,环境变量天然可得),切焦点后
select-window/select-pane 同步 Mac 终端视图,语音注入也跟焦点走。门控与
语音同哲学:授权等待让位、录音优先。为什么做:多会话用户的"翻页"动作离
不开键盘,摇杆把它也拿到手边——与实体键授权是同一条产品逻辑。

## 四、可能的刁钻题(准备立场,不慌就行)

- **"AI 做的占比多少?"** → 不回避:编码执行层 AI 占大头;架构、需求、
  排障、验收是人。git 历史和需求文档的 grill 记录就是证据链。
- **"为什么不用 XX 新技术?"** → 承认权衡:"我们评估过,宪法口径段记录了
  理由"——不辩经,指向文档。
- **"固件为什么不用 FreeRTOS 更高级特性/组件化?"** → 范围管理:两周窗口
  90 人时,砍掉的东西记录在案——**知道不做什么也是工程能力**。
- **"这项目实际价值?"** → 回到需求:CLI Agent 用户离键盘时是盲的,状态/
  授权/语音三个痛点都是真实场景;干净室补完开源生态是社区价值。
- **"Windows 能跑吗?"** → 有准备:《Windows调试指南.md》能力对照——daemon/
  虚拟设备/烧录可移植,语音注入因 tmux 缺失暂不支持(替代方案已备忘)。
